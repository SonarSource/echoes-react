# New design language: implementation and exploration changelog

> Snapshot: 2026-08-18
> Branch: `marcio/new-design-language`
> Status: work in progress; includes staged architecture work and unstaged visual exploration

This document records the current worktree state so the visual experiments can later be converted
into deliberate design-system decisions. It is not a release changelog and should not be treated as
an approved API specification.

## Executive summary

The work has two distinct layers:

1. **Color architecture migration:** Option 2 Website-aligned brand primitives, independently
   authored light/dark semantics, component token contracts, temporary action strategies, component
   migrations, compatibility rules, and validation.
2. **Projects Playground exploration:** a fake product page used to tune surfaces, navigation,
   borders, radius, typography, badges, avatars, filters, and shell structure. Several choices here
   are intentionally local CSS-variable overrides and must be formalized before product adoption.

The target dependency chain is:

```text
brand primitives → light/dark semantic tokens → component tokens → components
```

## 1. Brand primitive architecture

### Source of truth

- Adopted only `option-2`, Website-aligned.
- Light and dark palettes are independently authored; dark is not generated by reversing light.
- Brand A and Brand B currently have identical values but remain separately owned.
- Exact values live in the palette JSON files and should not be duplicated into another source of
  truth.

Changes:

- Normalized `brand-A` and `brand-B` directories to lowercase `brand-a` and `brand-b`.
- Added separate base, light, and dark palette files beneath each brand.
- Updated Tokens Studio metadata and theme paths for the new nested structure.

## 2. Semantic color direction

The interface direction is predominantly monochromatic:

- **Gray:** surfaces, borders, text, neutral controls, generic information, focus, and selection.
- **Gray Alpha:** contextual hover, pressed, selected, and overlay treatments.
- **Blue:** AI, upgrade, upsell, pricing, and explicit feature emphasis only.
- **Green, yellow, red:** success, warning, and danger.
- **Teal, cyan, purple, magenta, orange:** primitive-only until adopted by a reviewed decorative or
  data-visualization contract.
- **Data visualization:** isolated from general product-interface semantics.

The semantic files are:

- `design-tokens/tokens/modes/light.json`
- `design-tokens/tokens/modes/dark.json`

Stable intent added or formalized includes:

- `action`
- `interaction`
- `selection`
- `focus`
- `feature`
- `status`
- `dataViz`
- `decorative`

Legacy `accent` and `emphasis` remain frozen for compatibility. New work must not use `accent` as a
catch-all role.

### Radix twelve-step grammar

| Steps | Intended usage                               |
| ----- | -------------------------------------------- |
| 1–2   | Application and subtle backgrounds           |
| 3–5   | Component backgrounds and interaction states |
| 6–8   | Borders and separators                       |
| 9–10  | Solid fills and hover states                 |
| 11–12 | Readable text and high-contrast foregrounds  |

## 4. Component-token contracts

Added `component/light.json` and `component/dark.json` contracts so components no longer consume
raw primitives or broad semantic tokens directly.

| Component area      | Contract/direction                                                      |
| ------------------- | ----------------------------------------------------------------------- |
| Button              | Primary, secondary, ghost, danger, disabled, foreground, border, focus  |
| Link                | Action, default, subtle, hover, focus                                   |
| Input/Search/Select | Background, foreground, icon, border, validation, disabled, focus       |
| Checkbox            | Default, hover, selected, disabled, error, focus                        |
| Radio button        | Default, hover, selected, disabled, error, focus                        |
| Navigation items    | Default, hover, pressed, selected, disabled, subtle text, focus         |
| Table/Issue row     | Border, hover, selection, selection hover                               |
| Message             | Information, success, warning, danger, feature                          |
| Badge               | Weak and solid variants for neutral/status plus frozen legacy highlight |
| Badge counter       | Default and accent contracts                                            |
| Promoted feature    | Explicit feature background, border, and foreground                     |
| Promoted section    | Neutral, feature, and frozen legacy highlight contracts                 |

Migrated runtime files include buttons, links, inputs, selects, checkboxes, radio buttons,
navigation, tables, messages, badges, badge counters, and promoted sections.

Notable behavior changes:

- Primary buttons now follow `action.primary`.
- Secondary and ghost buttons remain neutral under both strategies.
- Link varieties use link component tokens rather than broad text/accent tokens.
- Checkbox indicators now use explicit flex centering and zero line-height so checked and
  indeterminate marks remain centered inside the control.
- Select now tracks and exposes `aria-expanded` while the dropdown is open.
- Closed sidebar navigation is marked `inert`.
- Message icons inherit the message contract color rather than choosing independent icon tokens.
- Added `PromotedSectionVariety.Feature` for verified AI, upgrade, upsell, pricing, or explicit
  feature promotion.
- Existing Highlight/emphasis treatments remain frozen pending consumer audit.
- `echoes.typography.code.highlight` was not changed.

## 5. Quiet control borders

Secondary buttons and resting form controls were changed to quieter neutral borders, with stronger
hover borders.

| Mode  | Resting border | Hover border |
| ----- | -------------- | ------------ |
| Light | `#C9CED6`      | `#8C929B`    |
| Dark  | `#474E57`      | `#616A75`    |

Focus, validation, selected, and disabled states retain dedicated mappings.

Important accessibility note: the resting borders intentionally fall below the WCAG 2.2 3:1
non-text contrast threshold against the default surface. Hover borders and keyboard focus remain
stronger. This tradeoff must be explicitly reviewed before claiming full conformance.

## 6. Radius changes

Added `echoes.borderRadius.300 = 6px` to both brand base files and regenerated the base artifacts.

Current radius decisions:

| Element                              | Radius           |
| ------------------------------------ | ---------------- |
| Buttons                              | 6px              |
| Cards                                | 6px              |
| Form-control default token           | 6px              |
| Select trigger/dropdown/clear button | 6px              |
| Checkboxes                           | 4px              |
| Playground account avatar            | 6px              |
| Playground “New” badge               | Full/pill radius |

The 6px changes began as visual exploration and are currently implemented in shared component code,
not only in the Playground. They require full regression review before release.

### Small typography size

The authored `echoes.fontSize.10` primitive increased from `0.75rem` (12px) to `0.8125rem` (13px)
in both brands. Typography roles that intentionally share this primitive—small text, helper text,
and x-small headings—inherit the new size while retaining the existing 16px line height.

## 14. Semantic elevation migration

Added six intent-based shadow roles while retaining the existing `boxShadow` scale as a public
compatibility layer:

| Semantic role       | Primitive alias    | Intended use                                               |
| ------------------- | ------------------ | ---------------------------------------------------------- |
| `shadow-suppressed` | `none`             | Explicitly cancel inherited or stacked elevation.          |
| `shadow-resting`    | `boxShadow.xsmall` | Bordered interactive or contained surfaces at rest.        |
| `shadow-attached`   | `boxShadow.small`  | Structural chrome lifted from the page plane.              |
| `shadow-anchored`   | `boxShadow.medium` | Dismissible overlays anchored to a trigger.                |
| `shadow-overlay`    | `boxShadow.large`  | Independent layers covering page content.                  |
| `shadow-over-data`  | `boxShadow.xLarge` | Surfaces requiring separation above dense data or imagery. |

Component shadow declarations now consume these semantic roles. Explicit shadow suppression remains
in place for disabled selection cards and focused toast containers, and resting shadows remain paired
with borders. Popovers and filter dropdowns now use anchored elevation. Nested dropdown submenus use
overlay elevation, preserving one elevation tier above their anchored parent menu.

Sidebar navigation group labels now use 6px horizontal padding instead of 8px, aligning their text
with the compact sidebar item spacing used by the playground shell.

The Storybook palette comparison now normalizes light-theme `color-surface-default` to the shared
white support token for the Website-aligned, Radix-generated, and Shadcn UI palettes. Canvas and
interaction colors remain palette-specific, and dark-theme surface mappings are unchanged.

The Issues playground now composes its search and filter controls with the public Echoes `Toolbar`
instead of a local flex wrapper. Its table rows are fixed at 52px for the compact prototype by
deriving that height from the existing 53px row token minus the 1px border token.

The Issues playground dataset now spans three pagination pages with 15 sample issues per page, so
the Echoes pagination control can be tested beyond its single-page state.

The Issues playground locally restyles severity badges for dense table scanning: issue quality is
now subtle supporting text, severity remains the only colored pill, and the two values sit together
as a compact risk group. The shared `BadgeSeverity` component is unchanged.

The Issues impact treatment now uses a compact neutral pill with a 4px severity-colored square,
severity label, quiet divider, and software-quality attribute (for example,
`High | Reliability`). The separate Clean Code Attribute column remains unchanged.

The Issues toolbar now uses an Echoes toggle button group for `All` and `Most impact`; the latter
shows high-severity issues. Issue titles truncate with their full text preserved in the native title
attribute, and the Issue column is capped so the Risk column stays visually associated with each
title while Code location absorbs the remaining flexible width.

The standalone Issues bulk-action row has been removed. The Issue column header now reveals the
